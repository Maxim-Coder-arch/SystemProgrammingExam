# Сценарии проверки

Перед проверкой из корня решения выполните `dotnet build`. Ожидается `0 Error(s)` и ни одного предупреждения.

## Сценарий 1. Библиотека подключена через ProjectReference и даёт два публичных метода

1. `dotnet run --project src/SystemInfoLibrary.ConsoleApplication`
2. В разделе «Задания 1 и 2» строка «Библиотека есть в ссылках сборки потребителя» равна `да`, а «Файл библиотеки» указывает на `SystemInfoLibrary.dll` рядом с приложением.
3. В разделе «Задание 3» выведены PID и сведения о платформе: ОС, архитектура системы и процесса, размер указателя (8 для x64).

## Сценарий 2. PID через P/Invoke совпадает с управляемым

1. В том же запуске найдите раздел «Задание 5».
2. «Использован нативный вызов» равен `да`, а «PID из kernel32 GetCurrentProcessId» совпадает с «PID из Environment.ProcessId».
3. Откройте Диспетчер задач, вкладку «Подробности». Процесс `SystemInfoLibrary.ConsoleApplication.exe` имеет тот же PID, пока приложение ждёт нажатия Enter.

## Сценарий 3. Ошибки нативных вызовов обрабатываются, а не роняют приложение

1. В разделе «Задание 7» четыре сценария:
   - `kernel32.dll` загружен: вызов успешен, выведен дескриптор модуля;
   - незагруженный модуль: `NativeFunctionReturnedWin32Error`, код Win32 `126`;
   - отсутствующая точка входа: `NativeEntryPointNotFound`;
   - отсутствующая библиотека: `NativeLibraryNotFound`.
2. После сценариев приложение продолжает работу и выводит задания 8–10.

## Сценарий 4. Обе программы используют одну и ту же DLL

1. `dotnet run --project src/SystemInfoLibrary.SecondConsumerApplication`
2. «MVID библиотеки» во втором приложении совпадает с «MVID библиотеки» из задания 1 первого приложения.
3. AssemblyVersion и FileVersion библиотеки во втором приложении — `2.0.0.0`, как в задании 8 первого приложения.

## Сценарий 5. Версии, совместимая обёртка и сравнение DLL

1. В разделе «Задание 8» у `SystemInfoLibrary` AssemblyVersion и FileVersion `2.0.0.0`, у консольного приложения — `1.0.0.0`.
2. В разделе «Задание 9» результат старого метода `GetCurrentProcessId` совпадает с новым API (`Результаты совпадают: да`). При сборке потребителя без `#pragma` компилятор выдаёт предупреждение CS0618 с подсказкой нового метода.
3. В разделе «Задание 10» у `SystemInfoLibrary.dll` есть заголовок CLR и флаг `ILOnly`, файл читается как сборка .NET. У `kernel32.dll` заголовка CLR нет, машина `Amd64`, как сборка .NET файл не читается.
